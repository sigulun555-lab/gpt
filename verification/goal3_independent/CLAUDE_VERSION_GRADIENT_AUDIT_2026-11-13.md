## Finding: gradient does not apply the derivative of the clipping operation

The pinned `fit().objgrad()` computes clipped logits:

```python
lh = np.clip(mu + h + att[hi] - dfn[ai], -20, 20)
la = np.clip(mu + att[ai] - dfn[hi], -20, 20)
```

but then uses unmasked residuals:

```python
eh, ea = L - yh, R - ya
```

For the stated objective, the chain rule through `clip` requires a zero derivative when a raw logit is strictly outside (-20, 20). The matching reference convention in GPT's pinned `nested_validation.py` is:

```python
eh = (lh - hg) * ((eta_h_raw > -20) & (eta_h_raw < 20))
ea = (la - ag) * ((eta_a_raw > -20) & (eta_a_raw < 20))
```

The issue is confined to this separate `goal3_versions.py` runner. Claude's 472-target `analysis.py` imports the pinned GPT `nested_validation.py` and therefore uses the masked-gradient implementation; the 472-target analysis path is not the unmasked `goal3_versions.py` implementation.

## Independent finite-difference check

A synthetic two-team, one-match objective was evaluated at raw home/away logits of +21 (both clipped to +20):

- Finite-difference objective gradient: all components 0 within numerical tolerance.
- Pinned Claude unmasked analytic gradient: maximum absolute component approximately `970330389.82`.
- A temporary research-only copy with the chain-rule mask: maximum absolute difference from finite differences 0 in this fixture.

The same source gradient agrees with finite differences in the unclipped interior fixture. This isolates the discrepancy to the clipped region rather than the general Poisson objective.

The portable test added to this PR reproduces both fixtures from the exact pinned source loaded by the existing provenance verifier. It preserves the upstream file bytes and tests a corrected temporary copy; it does not rewrite Claude's branch.

## Does this invalidate the reported 472-target comparison?

No such impact has been demonstrated.

The fixed retrospective 472-target comparison was generated by `analysis.py` using GPT PR #19's `nested_validation.py`, whose clipped-logit gradient is masked. Separately, the GPT provenance workflow ran the pinned Claude version runner's k=6 implementation on the fixed 429-row history and reproduced the 472 k=6 probabilities against Claude's all-k JSON with maximum absolute difference `2.0489165919457264e-12`. Thus no material k=6 output discrepancy was observed for this fixed dataset.

This parity result does **not** prove the unmasked runner is mathematically correct, does not prove clipping never occurred during every optimizer iteration, and does not validate the separate k=10 `goal3_versions.py` path over all 472 targets. Future data or different starting points can enter the clipped region. Do not use the unmasked runner for new research until it is corrected and independently retested.

## Other implementation distinction

The pinned Claude version runner calls L-BFGS-B with `gtol=1e-10` and no explicit `maxiter`; the nested-validation reference uses `maxiter=300` and the SciPy default `gtol`. They are not identical optimizer configurations. The existing parity check is empirical output parity for the tested data, not a proof of general solver equivalence.
